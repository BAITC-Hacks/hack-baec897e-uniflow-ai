# OrbitDuo Campaign Studio · frontend

React + TypeScript + Vite. Интерфейс показывает аудит аудитории, фактические пилоты,
журнал решений и сохранённый план. Прогноз агента отделён от результата локального
оценщика. Реальных рассылок нет.

## Как пользоваться интерфейсом

1. На обзоре проверьте доступную аудиторию и общие лимиты. Основное действие —
   «Подобрать кампании»; если расчёт уже идёт, обзор предложит вернуться к нему.
2. В «Аудитории» нажмите на уровень выручки или используйте поиск по тарифу и
   фильтр допуска. Таблица показывает по 15 групп; счётчик клиентов относится ко
   всем найденным группам. Фильтры, сортировка и страница сохраняются в URL.
3. В настройках выберите подход к риску. Для первого знакомства подходят
   сбалансированный подход и сценарий 42. В блоке «Номер сценария (необязательно)»
   можно изменить число; пустое или некорректное значение блокирует отправку.
4. На странице запуска следите за пробными проверками и действиями программы.
   После завершения начните с «Разбора результата»: он выделяет слабые места по
   сохранённым данным и ведёт к нужному предложению, проверке или замечанию.
   Сравните прогноз с проверкой в учебной среде, откройте подробности предложения
   и скачайте CSV или JSON. Длинные списки проверок и действий раскрываются по кнопке.
5. В «Запусках» найдите результат по коду, дате или номеру сценария. Доступны фильтры статуса
   и риска, порядок по дате и страницы по 15 записей среди последних 100 запусков.

Кнопка **«Справка»** в шапке доступна на каждом экране, включая телефон. Внутри —
поиск по объяснениям ARPU, пилотов, риска, прогноза, охвата, seed и экспорта.
Контекстные подсказки возле показателей и раскрываемые пояснения помогают
читать результат без обращения к документации. Справка и карточка кампании
поддерживают клавиатуру, закрываются Escape и возвращают фокус.

Основной экран переводит служебные сообщения сохранённых расчётов на русский:
вместо `queued`, `tariff_8` и `Posterior mean changed` видны этап, название тарифа
и объяснение изменения оценки. Исходные записи доступны в закрытых технических
деталях; CSV/JSON сохраняют исходные коды и данные. Для неизвестного формата
сообщения показывается нейтральное пояснение без выдуманной причины.

Разбор результата учитывает отрицательный вклад, отсутствие прямых проверок,
неопределённость прогноза, ошибки данных и остатки ресурсов. Это объяснение
сохранённого расчёта, а не отдельная модель оптимизации. Вручную добавлять и
удалять предложения здесь нельзя: новый подбор доступен с другим подходом
к риску или номером сценария. Одиночное отрицательное наблюдение не означает,
что предложение обязательно нужно исключить.

При ошибке обновления показанные данные сохраняются. Неопределённые оценки не
подменяются нулём. Демо продолжает работать при запрете localStorage, но
предупреждает, что история в таком случае доступна только до обновления вкладки.

После изменения интерфейса для обновления уже работающего локального Docker:

```powershell
docker compose up -d --build --no-deps frontend
```

## Предварительный калькулятор

Раздел **«Калькулятор»** (`/calculator`) доступен в навигации, на обзоре и перед
подбором. Выберите группу и канал, затем двигайте ползунки количества абонентов,
бюджета, вероятности перехода и изменения выручки. Числа можно вводить вручную.
Итог обновляется сразу; на телефоне он остаётся в закреплённой плашке.

Аудитория, средняя выручка и параметры каналов берутся из `GET /overview`.
Вероятность перехода и изменение выручки — предположения пользователя, исходные
10% приведены для примера. Для одного предложения и одной попытки связи:

```text
N = min(запрос, размер группы, лимит контактов, лимит кампании, доступные по бюджету контакты)
p = min(вероятность × коэффициент канала, 1)
эффект = N × средняя выручка × изменение выручки × p − N × цена контакта
```

При бесплатном контакте бюджет не ограничивает число получателей. Средняя выручка
взвешена по числу абонентов только в доступных группах. Промежуточные результаты
не округляются; денежные суммы на экране округлены до целых условных единиц.

Калькулятор показывает расходы, остаток бюджета, порог окупаемости, сравнение
каналов и график зависимости от отклика, включая точку насыщения вероятности.
Неполные или недопустимые значения не превращаются в нулевую оценку.

Это дополнительная выручка после расходов на связь за период исходных данных,
а не полная прибыль бизнеса. Модель не включает пилоты, пересечения, повторные
контакты и остальные расходы. Она не знает эффект конкретного целевого тарифа.
Калькулятор не создаёт запуск, не меняет сохранённый план и не передаёт свои
предположения в автоматический подбор. Кнопка под результатом открывает обычные
настройки нового подбора.

Формула и ограничения покрыты `tests/scenario-calculator.test.ts`; интерактивный
сценарий, сброс, клавиатура, пустые данные и мобильная плашка —
`tests/e2e/calculator.spec.ts`.

## Общий запуск через Docker

Из корня репозитория:

```powershell
docker compose up --build -d
docker compose ps
```

Открыть `http://localhost:8080`. Production-сборка использует настоящий backend:
`VITE_DEMO_MODE=false`, запросы `/api/v1` nginx передаёт сервису `backend:8000`.
Страницы запусков открываются по прямой ссылке и после обновления браузера.
`/healthz` проверяет frontend; `/api/v1/health` — backend.

Образ собирается в два этапа: Node 24 устанавливает зависимости по lock-файлу,
затем nginx работает непривилегированным пользователем на порту 8080.
В образ не включаются `.env`, `node_modules` с хост-машины и результаты тестов.
Переменные `VITE_*` задаются при сборке, поэтому после их изменения нужен rebuild.

## Локальная разработка

Для всех зависимостей, включая тесты, нужен Node **24.15.0 или новее в ветке 24**
(либо Node 26+). Более ранний Node 24 не удовлетворяет требованиям jsdom.

```powershell
cd frontend
npm ci
Copy-Item .env.example .env
npm run dev
```

По умолчанию включён настоящий API. Запустите FastAPI на `http://127.0.0.1:8000`;
Vite передаст ему запросы `/api/v1`. Для другого адреса можно установить
`VITE_API_BASE_URL`. При недоступности API интерфейс показывает ошибку соединения.
Автоматического перехода к демонстрационным данным нет.
Либо из корня выполните `powershell -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1`:
он запустит backend и Vite с `VITE_DEMO_MODE=false`.

## Проверки

```powershell
npm run build
npm run lint
npm run test
npx playwright install chromium
npm run test:e2e
npm run test:e2e:real
```

Unit-тесты проверяют ошибки API, отмену запросов, ETag/304 и повтор создания с тем
же ключом идемпотентности, даже если браузер запретил sessionStorage.
`test:e2e` самостоятельно запускает отдельный Vite с явным demo-режимом и проверяет
экспорт, reload, отрицательный прогноз, ошибку запуска и четыре ширины экрана.
`test:e2e:real` поднимает настоящий FastAPI, Vite с `VITE_DEMO_MODE=false`
и изолированную временную SQLite-базу. Для него нужен Python с backend-зависимостями
в `../.venv/Scripts/python.exe` или путь в `ORBITDUO_PYTHON`.
Если Chrome уже установлен, вместо скачивания Chromium можно задать
`$env:ORBITDUO_BROWSER_CHANNEL = 'chrome'` (для Edge — `'msedge'`).

При работающем общем приложении:

```powershell
$env:ORBITDUO_BASE_URL = 'http://127.0.0.1:8080'
npm run test:e2e:live
```

Live-тест создаёт настоящий локальный запуск. Он проверяет аудит, создание,
обновление страницы, завершение, лимиты, карточку кампании, историю и совпадение
скачанных CSV/JSON с сохранёнными файлами API. Тесты не обращаются к внешним
рекламным сервисам. Скриншот результата и артефакты ошибок сохраняются в
`test-results/`.

Дополнительные live-сценарии используют сохранённый API-снимок
`tests/fixtures/real-run.json`: проверяют русский основной текст, раскрытие
исходников, переходы из анализа, клавиатурный фокус и ширину 390 px.
Эти сценарии подменяют только чтение снимка и не создают новых запусков.

## Демонстрационные сценарии

Для разработки без backend явно задайте `VITE_DEMO_MODE=true` и перезапустите Vite.
В интерфейсе появится метка «Демо · синтетические данные». Запуски хранятся в
localStorage: seed `42` показывает положительный план, `7` — отрицательный прогноз,
`13` — ошибку. Осторожный риск-профиль уменьшает демонстрационную оценку.
Это fixtures интерфейса, а не измеренные результаты агента.

Для пустой аудитории в DevTools:

```javascript
localStorage.setItem('orbitduo-demo-fixture', 'empty')
```

После обновления страницы создание плана будет отключено. Чтобы вернуть обычное
демо, удалите этот ключ. Сводка `src/mocks/overview.json` получена из исходного CSV
командой `python scripts/generate_demo_overview.py`.

## Интеграция

API-клиент и DTO находятся в `src/lib/api/`; договор —
[`docs/team/API_CONTRACT.md`](../docs/team/API_CONTRACT.md).
Демо-транспорт `src/mocks/transport.ts` выдаёт те же DTO и ошибки.
Настоящий путь: `/overview` → `POST /runs` → polling `/runs/{id}` → сохранённый план и экспорт.
Polling активного запуска выполняется примерно раз в секунду, использует ETag
при поддержке сервером и прекращается после завершения. При сетевой ошибке
интерфейс сохраняет последний снимок и повторяет опрос; после перезагрузки
читает тот же `run_id`. Повтор POST после
неопределённого сетевого ответа использует прежний Idempotency-Key.

CSV в интерфейсе — сохранённый план выбранного запуска. Официальный конкурсный
файл создаётся отдельно из `participant_package/` командой `python make_submission.py`.
