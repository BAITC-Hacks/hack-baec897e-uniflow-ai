# Реализованный конкурсный контракт

`from agent import Agent; campaigns = Agent().act(env)` работает offline без аргументов,
API, ключей, БД и GPU. Необходимые файлы сдачи: `agent.py`, каталог `orbitduo/` с собственными
decision-модулями и публичная `data/change_tariff.csv` для исторического prior. Без истории
агент явно предупреждает и использует нейтральный prior. Зависимости: numpy/pandas.

Результат — от 1 до 10 непустых фактически исполнимых кампаний. Каждая содержит только:
`campaign_name`, `filter_arpu_segment`, `filter_data_segment`, `filter_call_segment`,
`filter_current_tariff`, `target_tariff`, `channel`. Неиспользованные фильтры — `None`.
`explicit_ids`, `top_k`, численные лимиты и фильтры произвольного дохода отсутствуют.

Тарифы/каналы читаются из публичных `env.tariffs`, `env.channels`; деньги/контакты — из
публичных остатков. Из среды разрешены только `customer_profile`, `tariffs`, `channels`,
`total_budget`, `max_total_contacts`, `remaining_budget`, `remaining_contacts`, `pilots_left`,
`pilot_history`, `run_pilot`. Текущая реализация не нуждается даже в чтении `pilot_history`:
полные собственные запросы и возвращённые ответы хранятся самостоятельно.

Общие лимиты: 100 000 CU, 15 000 контактов с повторениями и пилотами, 20 пилотов,
10 финальных кампаний, до 5 000 фактических клиентов в одной финальной кампании.
Запрос пилота — 10–200; фактическая выборка может быть меньше 10. Минимум один
успешный пилот обязателен и обновляет posterior до окончательного выбора.
Стандартная стратегия имеет дополнительный внутренний предел 16 пилотов.

Публичный scoring сортирует аудиторию по ID, затем ограничивает 5 000, контактами
и деньгами. Порядок важен. На клиента учитывается лучший эффект всех кампаний,
включая отрицательный максимум; затраты списываются на каждый контакт.
`predicted_arpu` — baseline, цель — дополнительный `gross_gain − communication_cost`,
не полная прибыль оператора. Конкурсный тариф/сегмент нельзя выдумывать из пропусков.

Различия с исследовательскими предложениями разрешены в пользу исходников:

- API публичного пилота не возвращает ID и полные фильтры; пересечение с пилотами
  оценивается, а не заявляется точным.
- Нет возможности передать отсортированный ARPU top-k: итоговая сортировка только ID.
- Канал call насыщается; перенос из push без отдельного пилота не используется.
- Гайд допускает 10 минут, шаблон — 5; внутренний предел принят 5 минут с резервом.
- Частоты состоявшихся исторических переходов не считаются conversion или causal uplift.
- Потенциальный local_eval exit 0 сам по себе не доказывает валидность: отдельный
  adapter проверяет число кампаний, фактический охват, пилоты, санитаризацию и ресурсы.

Неизменяемые организаторские файлы: `environment.py`, `scoring_core.py`,
`mock_environment.py`, `local_eval.py`, `make_submission.py`, `agent_template.py`
и входные CSV. `submission.csv` генерируется штатным `python make_submission.py`;
API-export строится из сохранённого конкретного run, без повторного запуска стратегии.

Дополнительная конфигурация для исследований: `Agent(seed=42, risk_profile='balanced',
observer=None, use_history=True, adaptive=True, risk_penalty=None, allowed_channels=None,
max_pilots=16, history_strength=1.0, diverse_fixed=False, strategy_version="v2",
calibrate_prior=True, advanced_search=True)`. Параметры не изменяют обязательную точку входа.

в `approach.md`. Прогноз, пилотные наблюдения и независимый итог evaluator разделены.
