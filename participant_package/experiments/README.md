# Воспроизводимые офлайн-эксперименты

Все команды выполняются из `participant_package/` с активированным виртуальным окружением репозитория. Агент работает без сервера и получает только публичный `env`. Таблицы истинных эффектов и реальные ID пилотов использует отдельный harness для локальной оценки; они не передаются в решающий код.

## Текущая v2 и архив v1

| Расположение | Содержание |
|---|---|
| `agent.py`, `orbitduo/` | Текущий стандартный `Agent()`: версия v2, `advanced_search=True`. |
| `experiments/reference_v1/` | Зафиксированный код первой версии для парного сравнения. Изменён только путь к истории; исходные хэши находятся в `manifest.json`. |
| `reports/v1/` | Архив измерений первой версии: baseline, benchmark, ablation, сценарии и диагностики. Эти результаты не описывают текущий `Agent()`. |
| `reports/v2_advanced/` | Первые измерения v2 с расширенным поиском. |
| `reports/v2_simple/` | Измерения временно упрощённой v2, `advanced_search=False`. |
| `reports/improvement*` | Парные проверки сохранённой v1 и текущей v2, предварительные серии и отдельная проверка новых таблиц эффектов. |
| `reports/v2_ablation*` | Проверки компонентов текущей v2. |
| `reports/planner_benchmark.json` | Сравнение планировщиков на одинаковом сохранённом posterior и остатках ресурсов. |

В отчётах сравнения метка `new` означает v2, а `v1` означает `experiments.reference_v1.Agent`. Настройка `Agent(strategy_version="v1")` в текущем коде использует современные общие модули и не заменяет зафиксированную архивную реализацию.

Архив `reports/v1/` сохраняется отдельно. Старые команды `benchmark`, `diverse_fixed`, `sensitivity` и `summarize` не закреплены за кодом v1 и работают с текущими файлами в верхнем каталоге `reports/`; их повторный запуск не воспроизводит автоматически архив v1.

## Парное сравнение v1 и v2

```powershell
python -m experiments.improvement --scope full --versions both
python -m experiments.improvement --scope model_holdout --versions both
python -m experiments.improvement --scope final_holdout --versions both
```

Первая команда сохраняет `improvement.csv` и `improvement_summary.json`: 76 измерений, по две версии на каждую комбинацию сценария и seed.

- `mock_tuning`: seed среды 0-9; seed 0-2 использовались при предварительном выборе варианта.
- `mock_heldout`: контрольные seed среды 20-29, повторно использованные после структурного упрощения; теперь это не новая независимая проверка.
- Шесть изменённых семейств: seed среды 10-12, seed генератора моделей 20260924 плюс индекс семейства. Таблицы эффектов и seed 10-11 уже использовались при предварительной проверке; seed 12 меняет выборки и шум, но не таблицу эффектов.

Вторая команда сохраняет `improvement_model_holdout.csv` и соответствующую сводку: шесть измерений на трёх таблицах с seed генератора моделей 20260925 и seed среды 31 для `permuted_leaders`, `weak_history`, `saturated_calls`. Эти таблицы были новыми в серии расширенной v2, но уже использовались до структурного упрощения. Повтор не является новой независимой проверкой; одного парного сравнения на таблицу недостаточно для статистической гарантии устойчивости.

Расширенный поиск временно отключили после первой контрольной серии: проверки компонентов на seed 0-2 и диагностика фиксированного posterior не показали выигрыша. Более широкое парное сравнение затем выявило заметную пользу, особенно при насыщенных звонках. Поиск восстановили до передачи результатов свежей серии лицу, принимавшему решение. Другие параметры не менялись. Оба шага явно записаны в metadata; артефакты сохранены в `reports/v2_advanced/` и `reports/v2_simple/`. `improvement_search_comparison.csv/json` сравнивают эти варианты на одинаковых сценариях, исключая свежую серию.

Третья команда выполняет заключительную проверку окончательной версии: пять mock-seed 40, 41, 43, 44, 45, по одному запуску v1 и v2. Из первоначально предложенного диапазона 40-44 исключён многократно проверявшийся стандартный seed 42, вместо него добавлен 45; это исправление состава контрольной серии, а не выбор по результатам. Результаты временно упрощённой версии на этих seed были получены отдельно, но не передавались для выбора окончательного режима. Финальная серия с восстановленным поиском выполняется после фиксации; дальнейшей настройки нет. Команда сохраняет `improvement_final_holdout.csv` и сводку, использует отдельный кэш. Новыми являются выборки и шум; таблица истинных эффектов mock остаётся прежней.

Собственный seed обоих агентов равен 42, как в стандартном конкурсном запуске. Одинаковый seed среды обеспечивает парное сравнение, но разные политики выбирают разные пилоты; их наблюдения не обязаны совпадать.

Harness проверяет ограничения и неизменность решающих исходников после каждого нового измерения. Сводки содержат фактически использованные настройки и SHA-256 кода, данных и моделей. Результаты v1 кэшируются в `improvement_reference.csv` с отдельным manifest; новые таблицы используют другой кэш. Несовпадение хэшей останавливает повторное использование кэша. Перед намеренным изменением исходных данных или сохранённой v1 архивируйте соответствующий кэш и manifest вместе.

`reports/improvement_report.md` объясняет результаты и ограничения на русском. Среднее, p10 и результат seed 42 рассматриваются отдельно: улучшение среднего не означает выигрыша в каждой паре. p10 по десяти запускам является грубой описательной оценкой.

Для новой ограниченной диагностической серии текущего кода:

```powershell
python -m experiments.improvement --scope quick --versions both --label review
```

Она использует mock-seed 0-2 и seed семейств 10-11. Это серия для разработки, а не независимая контрольная проверка. Сохранённые `improvement_quick_checkpoint1*` и `improvement_quick_risk055*` относятся к указанным в них версиям кода; повтор команды запускает текущую реализацию.

## Проверки компонентов v2

```powershell
python -m experiments.v2_ablation
```

Команда выполняет 21 запуск на одинаковых seed среды 0-2 и сохраняет `v2_ablation.csv`, `v2_ablation_summary.json`, `v2_ablation_notes.json`.

| Вариант | Изменение относительно стандартной v2 |
|---|---|
| `v2` | Текущая стандартная стратегия. |
| `no_history` | Отключена историческая информация. |
| `fixed_prior` | Отключена адаптивная калибровка исторического prior. |
| `fixed_diverse` | Зафиксировано разнообразное расписание гипотез и каналов; posterior продолжает обновляться. |
| `no_risk_penalty` | Риск-штраф равен нулю. |
| `push_only` | Разрешён только push. |
| `basic_planner` | Отключены штрафы за деньги и локальный поиск каналов/порядка; сохранён кэшированный жадный планировщик. |

Это чувствительность компонентов на трёх уже использованных seed одной mock-модели, без доказательства универсального превосходства каждого компонента. Варианты задаются параметрами отдельного экземпляра агента; файлы ядра не изменяются.

## Отдельное измерение планировщика

```powershell
python -m experiments.planner_benchmark
```

На seed 42 сначала выполняется сохранённый агент v1. Затем его собственные публично полученные posterior, сведения о пилотах и остатки ресурсов фиксируются для трёх вариантов:

1. Исходный планировщик v1.
2. Кэшированный планировщик с той же целевой функцией, без новых штрафов за деньги и локального поиска.
3. Расширенный поиск с дополнительными штрафами за деньги и локальными изменениями каналов/порядка, включённый в окончательном `Agent()`.

Перед замером проверяется точное совпадение спецификаций, порядка и фактических аудиторий первого и второго вариантов. Каждый вариант вызывается пять раз с чередованием; измеряются только вызовы планировщика, без загрузки данных и пилотов. `planner_benchmark.json` сохраняет отдельные времена, медианы и ускорение. Это отделяет ускорение кэша от изменения разведки и качества стратегии.

## Модели эффектов и корректность

Новые семейства в `improvement.py` отличаются от архивных сценариев с seed модели 20260923: переставляются лидеры, меняются знаки с дополнительным изменением величины эффекта, ослабляется связь с историей, снижается конверсия, насыщаются звонки либо создаются почти нулевые эффекты. Конструкции и хэши таблиц фиксируются в сводках. Это синтетические проверки, а не оценки скрытого судейского распределения.

Каждый строгий запуск проверяет разрешённые поля и каналы, успешные пилоты, 1-10 непустых финальных кампаний, фактические аудитории до 5000 клиентов, суммарные контакты и бюджет, время меньше 300 секунд. Некорректная новая стратегия останавливает эксперимент. Ошибки исходного шаблона в его отдельных измерениях сохраняются как `conforms=false`.

Результаты включают пилоты. `runtime_seconds` измеряет `act()`, кроме отдельно обозначенного измерения планировщика. Оценка неизвестных пересечений с пилотами не использует реальные ID в оптимизаторе. Архивная диагностика Monte Carlo находится в `reports/v1/overlap_sensitivity.json`; стандартная ошибка симуляции в ней не является интервалом неопределённости эффекта.

## Тесты и конкурсная проверка

```powershell
python -m pytest -q
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Смысловые тесты проверяют отрицательный максимум контактированного клиента, лучшую не последнюю кампанию, повторные контакты, порядок ID и границу 5001 клиента, ресурсы, реальные размеры пилотов, пропуски, posterior, перенос между каналами и насыщение. `tests/test_v2.py` дополнительно проверяет точное перечисление пересечений, совпадение кэшированного расчёта с независимым перебором по клиентам и fallback с минимальным оценённым ущербом с учётом риска.

`local_eval.py` перехватывает ошибки агента, поэтому его успешный exit code сам по себе не подтверждает корректность стратегии. Строгие парные эксперименты и тесты проверяют фактический результат. `make_submission.py` отдельно создаёт официальный план стандартного `Agent()` на seed 42; API-экспорт конкретного запуска выполняется независимо.
