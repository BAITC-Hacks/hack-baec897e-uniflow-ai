# Локальный API UniFlow

Запускайте из корня репозитория в проверенном Python-окружении:

```powershell
.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
.venv/Scripts/python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Используйте **один** процесс сервера: расчёт выполняется в отдельном потоке.
Несколько uvicorn workers запускать нельзя. Блокировка операционной системы
отклоняет второй сервер с той же базой до восстановления заданий, поэтому он
не может ошибочно завершить активный расчёт первого сервера. Блокировка
освобождается после штатного завершения или остановки процесса. Файл
`.server.lock` может остаться на диске; удалять его при работающем сервере нельзя.
Транзакции SQLite и частичный уникальный индекс обеспечивают атомарную
регистрацию при одновременных запросах. База по умолчанию —
`backend/data/runs.sqlite3`; другой путь задаётся через `UNIFLOW_DB_PATH`.

При запуске сервера прерванные задания сохраняются со статусом ошибки
`SERVER_RESTARTED`. Завершённые результаты, экспорт и ключи идемпотентности
переживают перезапуск. Снимки со статусами `completed` и `failed` неизменяемы:
запоздавший callback прогресса не может изменить опубликованный результат.
Существующая база **мигрирует автоматически**, сохраняя результаты и ключи.
Список запусков читает сохранённые краткие сводки без разбора полного журнала.

OpenAPI: `http://127.0.0.1:8000/docs`. Маршруты и DTO реализуют
`docs/team/API_CONTRACT.md`. Frontend может обращаться через Vite proxy
`/api/v1` или явный базовый URL API; для локального Vite на порту 5173 разрешён
CORS. Каждый POST `/api/v1/runs` требует заголовок `Idempotency-Key` и тело:

```json
{"seed":42,"risk_profile":"balanced"}
```

Повторный запрос с тем же ключом проверяется в SQLite до загрузки исходных
данных. Это позволяет получить сохранённый запуск после перезапуска, даже если
входные файлы недоступны. Такой запрос возвращает существующий результат;
для нового расчёта нужен новый ключ и доступные корректные данные.
Аудит исходных данных выполняется при запуске, до готовности HTTP-сервера,
поэтому первый POST не ждёт первоначального чтения CSV и импорта библиотек.
Если входные файлы недоступны, сервер сохраняет доступ к прежним результатам
и записывает ошибку аудита в журнал.

`GET /api/v1/runs/{id}` возвращает заголовок `ETag`. При следующем опросе
клиент может передать его в `If-None-Match`. Если снимок не изменился, сервер
вернёт `304` без тела: интерфейс продолжает отображать предыдущий снимок.
При изменении вернутся `200`, новый снимок и новый `ETag`. Без `If-None-Match`
клиент по-прежнему получает полный ответ по общему контракту.
Идентификаторы и порядковые номера уже опубликованных событий сохраняются
при росте журнала; события очереди, запуска и оценки остаются рядом
с событиями агента.

Worker импортирует отдельный адаптер оценки при выполнении расчёта.
Каждый запуск получает новую среду и нового агента. Прогноз, шумные пилотные
наблюдения и результат официального локального оценщика передаются в разных
полях. CSV содержит только семь полей кампаний сохранённого запуска;
экспорт не запускает агента повторно.

Команды проверки; для `backend.smoke` сервер должен быть уже запущен:

```powershell
.venv/Scripts/python.exe -m pytest backend/tests -q
.venv/Scripts/python.exe -m backend.benchmark_storage
.venv/Scripts/python.exe -m backend.smoke --base-url http://127.0.0.1:8000/api/v1
.venv/Scripts/python.exe -m backend.final_smoke
```

`backend.final_smoke` самостоятельно запускает отдельный HTTP-сервер с временной
базой, выполняет `balanced` / seed 42, сравнивает CSV побайтно с
`participant_package/submission.csv` и повторяет проверки после перезапуска.
Он проверяет сохранность снимка, идемпотентность и `ETag`, затем записывает
измерения и SHA-256 исходников в `backend/reports/http_final_smoke.json`.
Команду запускают после штатной генерации актуального submission.

Бенчмарк хранилища использует `backend/reports/http_smoke.json` и временную
базу. Он сравнивает прежнее чтение списка через полные снимки с чтением кратких
сводок и сохраняет измерения в `backend/reports/storage_benchmark.json`.
Сохранённые запуски сервера не изменяются. Эти измерения характеризуют
операции хранилища; задержку HTTP нужно измерять отдельно.
